Fast tests: your steps

The plan makes Magenda iPad-only and cuts a pull request's test run to 20 minutes. Most of it runs on its own; these three items need you. Tick each step as you go. The ticks are remembered in this browser only.

Before implementation

1. Check that Magenda has no App Store release

mb1-no-app-store-release

About 2 minutes

The plan removes iPhone support. Apple refuses an update that drops iPhone once a version supporting iPhone has been on the App Store. TestFlight builds do not count.

  1. Open App Store Connect → Apps and sign in with the Apple Developer account.You should see the list of your apps, including Magenda.
  2. Click Magenda. Under App Store in the left column, look at the iOS versions listed.Only TestFlight builds (version 0.1.1 and later) are expected here, with no version shown as "Ready for Distribution" or "Removed from Sale".
  3. If a version was ever released on the App Store, stop. Do not run /implement. Tell the planning session instead, because the iPad-only part of the plan has to change.

Done when: the App Store tab for Magenda shows no version with status "Ready for Distribution" or "Removed from Sale", only TestFlight builds. Then run /implement.

After implementation

2. Apply the new required checks

ma1-apply-required-checks

About 5 minutes, just before you merge the pull request

The pull request replaces the 19 required checks with 7. Until branch protection matches, GitHub waits for app (…) checks that no longer run, and the pull request cannot merge.

Merge pull requests #16 and #17 first. Once the new list is applied, any open pull request still running the old workflow is blocked.

  1. Open the feature/fast-tests pull request and check that its latest Tests run is green. It should have the jobs core, lint, scripts and ui (ipad, newest, 1) to ui (ipad, newest, 4).
  2. On a computer where the GitHub CLI is signed in as a repository admin, check out the branch:
    git fetch origin feature/fast-tests
git checkout feature/fast-tests
gh auth status
    gh auth status should show you as logged in to github.com.
  3. Compare the live rules with the new list (what the script does):
    python3 scripts/update_branch_protection.py show
    It should list the old app (…) and iPhone ui (…) checks as live, and the seven new checks as wanted.
  4. Apply the new list:
    python3 scripts/update_branch_protection.py apply
  5. Reload the pull request. Under its checks, only the seven new ones should be marked Required. You can also see them in Settings → Branches.

Report back: tick this item in the pull request, or paste ma1: applied, 7 required checks as a comment.

3. Check the iPad build on a real iPad at the next release

ma2-ipad-testflight-smoke

About 5 minutes, after the next release tag is uploaded

CI cannot check that an iPad-only build installs from TestFlight and opens the binder on real hardware. This is owed at the next release, not before the merge.

  1. After the next release, open TestFlight on a real iPad and install the new Magenda build.
  2. Open Magenda, sign in, tap Render, and write a line on the first binder page with Apple Pencil.The binder opens with its page indicator, and your ink stays after you swipe to the next page and back.
  3. Follow the rest of the iPad section of the release testing checklist as usual.

Report back: add iPad-only build: installs and renders the binder — pass/fail to the release's testing notes.
