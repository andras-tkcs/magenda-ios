Magenda iPad setup

plan/google-agenda-pdf · manual steps

The iPad Magenda builds your daily binder straight from Google Calendar and Google Tasks with fixed rules and no AI. It ships without any Google client: you create your own in your Google Cloud project and type its client ID into the app. Everything here happens after the work is done, before the pull request merges.

Tick each step as you go. Ticks are kept in this browser only.

0 of 0 steps done

Before implementation

Nothing to do. Every phase runs against test data, and the app ships without a Google client, so you can run /implement straight away.

After implementation

Do these when the pull request for feature/google-agenda-pdf is open and CI is green. About 100 minutes. Paste each report line into the PR's “Manual verification” section.

1a. Create a Google Cloud project with the Calendar and Tasks APIs

ma1-google-cloud-client ~10 min

Every request the app makes to Google fails with “Google refused the request” until both APIs are enabled.

Done when both APIs show “API enabled” on their console pages for the Magenda iOS project.

1b. Configure the OAuth consent screen

ma1-google-cloud-client ~10 min

Google refuses sign-in until the consent screen exists with the two read-only scopes.

With External in Testing mode, Google ends a sign-in after 7 days and the app says “Your Google sign-in expired. Sign in again.” Internal has no such limit. If your Workspace admin blocks unknown apps, sign-in shows “Access blocked” until the admin trusts the client ID from step 3 in the Admin console (Security → API controls).
Done when the Audience page shows “Internal”, or Publishing status “Testing” with your address under Test users, and Data access lists both read-only scopes.

1c. Create an iOS OAuth client

ma1-google-cloud-client ~5 min

The app ships without a Google client. You enter this client ID in the app on first launch.

Done when the Clients page lists the iOS client “Magenda iOS” for name.felhasznalo.magenda.
