Magenda iOS setup

plan/google-agenda-pdf · manual steps

The iOS port of Magenda reads your Google Calendar and Google Tasks. A few things only you can do: create the Google Cloud project and sign-in client before the work starts, and check the finished app on a real iPhone before the pull request merges.

Tick each step as you go. Ticks are kept in this browser only.

Before implementation

Do these before you run /implement. About 25 minutes.

1. Create a Google Cloud project with the Calendar and Tasks APIs

mb1-google-cloud-project ~10 min

Every request the app makes to Google fails with “Google refused the request” until both APIs are enabled.

Done when both APIs show “API enabled” on their console pages for the Magenda iOS project.

2. Configure the OAuth consent screen in Testing mode

mb2-oauth-consent-screen ~10 min

Google refuses sign-in until the consent screen exists and your account is listed as a test user.

In Testing mode Google ends a sign-in after 7 days. The app then says “Your Google sign-in expired. Sign in again.” That is expected until the app is published and verified by Google, which is outside this work.
Done when the Audience page shows Publishing status “Testing” with your address under Test users, and Data access lists both read-only scopes.

3. Create an iOS OAuth client and commit its client ID

mb3-ios-client-id ~5 min

The app's sign-in uses this client ID. A check in scripts/tests fails until the file holds a real one.

Done when git show origin/plan/google-agenda-pdf:App/GoogleOAuthClientID.txt prints one line matching ^[0-9]+-[a-z0-9]+\.apps\.googleusercontent\.com$.

After implementation

Do these when the pull request for feature/google-agenda-pdf is open and CI is green. About 50 minutes. Paste each report line into the PR's “Manual verification” section.

1. Sign in, render, preview and share on a real iPhone

ma1-device-sign-in-render-share ~20 min

Google's sign-in page, the Keychain on a device and the share sheet cannot run in CI.

Report ma1: pass or ma1: fail — <which step, what you saw>

2. Long titles with real data and the largest text size

ma2-long-text-real-data ~15 min

Confirms the automated layout checks against real Google data and real fonts, as a person sees them.

Report ma2: pass or ma2: fail — <screen or page, what overlapped>

3. Delegated tasks from a Google Tasks list

ma3-delegated-list ~10 min

Confirms the notes format works when typed into the real Google Tasks app.

Report ma3: pass or ma3: fail — <what differed>

4. App Store Connect privacy answers

ma4-app-store-privacy ~5 min

The app reads Google data only on the device and sends nothing to you, so it collects no data. App Store Connect needs that answer before review.

Before a public App Store release, Google must verify the OAuth app because it uses sensitive scopes. That is a separate step, not part of this work; until then only test users can sign in.
Report ma4: done
