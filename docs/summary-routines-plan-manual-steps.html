Summary Routines Setup

Magenda will start one Claude routine per kind of summary instead of letting the end-of-day routine write them all. Nothing has to be done before the code is built. The three items below come after it, in this order.

0 of 0 done

Before implementation

Nothing. The phases build against fake routines, so no account, secret or console change is needed first.

After implementation

1. Adapt the end-of-day routine to schema 3

about 15 minWithout this the routine stops on every payload, the day's too.

Done when the saved prompt names schema /3, the two steps, and no summary work. Report back with one line, for example ma1: routine prompt updated to /3.

2. Create each summary routine and add it in Settings

about 20 min per routineRepeat for every kind of summary you want.

Done when every summary routine you want is listed in Settings, and at least one meeting title has a rule. Report back the routine names, for example ma2: Client memo, Decision log added. Never report a token.

3. Run a day on an iPad

about 25 minThe only check that uses the real routines, the marker and the Doc.

Done when the day reaches Closed through both approvals. Report back a pass or fail line for the pull request, for example ma3: pass, 1 summary routine, day closed, and which step failed if it did not.

Tokens only ever go into Magenda's Settings, which keeps them in the iOS Keychain. They do not belong in this page, in the repository, or in a chat.
